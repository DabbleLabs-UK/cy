# Corrected public-gist contract - fixed sixteen rerun

## Verdict: MERGE/DEPLOY recommended, not performed

The product contract now explicitly permits the minimum useful gist of opted-in
personal material, while excluding identifying details, raw-message reuse and
unnecessary sensitive specifics. The previous blanket exclusion of private
details was too broad. Under this corrected permission, employment loss plus
self-worth and pet-health waiting plus worry are legitimate associative topics.
This is not a claim that anonymisation alone grants permission: the existing
explicit per-exchange prospective opt-in remains mandatory.

## Contract and implementation

Default-unchecked, per-postcard wording:

> Allow Cy to remember a short, public-safe summary of this postcard and his reply,
> if published, and recall it in replies to other people. This does not allow raw
> message reuse or identifying details. The summary may keep the minimum useful
> gist of what you told Cy, but should leave out unnecessary sensitive specifics.
> Optional; leaving this off does not affect his memory of you in your own
> correspondence.

Formation receives the same meaning: retain the concrete useful topic, abstract
unnecessary precise circumstances, dates, workplaces, clinical details,
credentials and unique biographical combinations; generalise third-party
circumstances; honour explicit confidentiality. Null is still normal. The
POSTCARD versus CY_REPLY basis, UNCERTAIN scope, paired canonical sources,
sender-only original memories and four-word/raw-copy guards are unchanged.
Small additional identifier checks reject handles, UK postcode shapes and common
numbered street-address shapes. They are not semantic privacy verification.

The permission version remains compact-public-recall-v1 because this is still
the unreleased prospective implementation. No deployed consent was widened,
historical row authorised, migration run or old memory reprocessed.

and precise contact/location exclusion, prompt/checkbox semantics, unchanged
private formation and provenance. Full runner tests pass 581/581 using workspace
TEMP; the first invocation's 21 failures were sandbox TEMP rename EPERM errors,
not suppressed or fixed in product code. All 28 PHP suites pass, including 36
permission/public-summary checks. Syntax, manifest parsing and diff checks pass.

Four disposable MariaDB/API integration suites passed and cover the canonical sender
formation delivery, formation accounting, associative permission/formation/
retrieval and postcard retry lifecycle (4/4, zero skips/failures). The owned
database and PHP test children stopped afterward; no real provider is used by
those tests. Independent review found no blocking diff or accepted-output issue
under the revised permission contract.

Deployment is recommended only under the corrected user-approved product
contract. It still requires coordinated migration 032/server/runner/form rollout
and prospective permission; this rehearsal performs none of those actions.
Automatic abstraction remains fallible, uncommon/lower-case identifiers and
paraphrased confidential facts are not exhaustively detected by structural
guards, and lexical retrieval may miss associations or return a weaker second
match. Natural post-rollout evidence should be inspected without claiming a
general semantic privacy guarantee.
