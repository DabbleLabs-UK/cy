async-select

A confirmation-aware select. A choice is a request, not a fact: the control shows the requested value as explicitly provisional until the server confirms it, and stays honest through rejection, failure, timeout, superseding and external changes.

Every control below shares one implementation. Use the keyboard (Tab to it, then Down/Up/Home/End/Enter/Esc, or type to jump). Watch the status line under each control and the event log.

solid = confirmed / authoritative dashed + tag = requested, not yet true ✓ = server value ··· = in-flight request

1. Instant success (< 150 ms)

Below the latency threshold the control shows no pending state at all - no spinner flash. It settles straight to a quiet tick.

2. Slow success (800 ms)

Past the threshold, the requested value shows as provisional (dashed, tagged requested) with a spinner and the current authoritative value spelled out. On confirm it settles quietly.

3. Very slow success (4 s) - escalation

After ~3 s the message escalates to "Still saving..." and the live region re-announces. The control is never blocked - you can still open it and pick again.

4. Rejection with a reason

The server refuses. The control reverts to the authoritative value and states specifically why. Try the disabled option too - it is announced as unavailable and never requested.

5. Network failure - recoverable

The request errors. The control keeps the attempted value visible (tagged unsaved), never silently reverts, and offers Retry. Retry here succeeds the second time.

6. Timeout

The commit never settles. After the configured timeout (2 s here) the control gives up, explains it timed out, keeps the attempted value, and offers Retry.

7. Superseding change (change your mind mid-flight)

A slow (3 s) request is in flight when a newer choice is made. The newer request wins; when the stale response lands it is ignored (guarded by a request sequence number, not by ordering). Press the button, or do it by hand: pick "Draft", then immediately pick "Published".

8. External change mid-flight

While a 3 s request is in flight, the authoritative value changes elsewhere (another tab / another user). The control reconciles the baseline without stealing focus and without discarding your in-flight intent. It announces the external change quietly.

9. Local (instant) options + disabled state

The same component also serves options that need no server confirmation - marked instant, they apply immediately. The toggle disables the whole control (UNAVAILABLE).
