async-select

A confirmation-aware select. A choice is a request, not a fact - so the requested value reads as provisional until the server confirms it, and the control stays honest through rejection, failure, timeout, superseding and external change.

Every state is expressed inside the select's own footprint: one glyph in the chevron slot, plus a border/wash tint. No status row, no error field, no layout shift. A plain <select> sits beside each one so you can check the box never grows.

dashed italic value = requested, not yet true spinner = saving tick = confirmed ! tint = rejected / failed (hover for why; click to recover)

Instant success (< 150 ms)

Below the latency threshold: no spinner flash, straight to a quiet tick.

plain

Slow success (800 ms)

Value goes dashed + italic with a spinner; settles to a tick on confirm.

plain

Very slow (4 s) - escalation

After ~3 s the spinner intensifies (thicker, warmer). No words added.

plain

Rejection with a reason

Reverts to the authoritative value; warning glyph, reason in the tooltip only.

plain

Network failure - recoverable

Keeps the attempted value (dashed), warning glyph. Click it to retry (succeeds 2nd time).

plain

Timeout (2 s)

Never settles; the control gives up, keeps the value, warning glyph retries.

plain

Supersede (change your mind mid-flight)

Newer pick wins; the stale response is ignored (guarded by sequence number).

plain

External change mid-flight

Authoritative value moves elsewhere: a momentary highlight, no text, no lost intent.

plain

Local (instant) options + disabled

Options marked instant apply with no server call. Toggle disables the control.

plain

Keyboard: Tab to a control, then Down/Up/Home/End to move, Enter/Space to choose, Esc to close, or type to jump. In a warning state, Tab reaches the glyph and Enter recovers. Outcomes are announced to screen readers via a live region; reasons via the tooltip and accessible description.
